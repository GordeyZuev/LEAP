## 📅 October 2026

### v0.11.1.0 — Home, добавление видео и просмотр (уточнено 2026-10-03)

#### Home — сводка при входе

- **Уточнение 2026-10-04:** Activity появляется только при наличии публичной записи LEAP с включённой ссылкой или доступного для воспроизведения видео в публичном плейлисте владельца; без публикаций запрос аналитики не отправляется. Нулевые просмотры за неделю не скрывают блок, если публикации есть. Исправлена гидратация вкладок Settings: быстрый ответ профиля больше не заменяет серверный скелетон до завершения гидратации панели.

- **Навигация:** после входа открывается `/home`; пункт Home отделён от остальных в сайдбаре. Вверху — название раздела и приветствие. **Open library** открывает каталог, а **Connect a source** помогает начать работу с пустой библиотекой. Добавление видео остаётся в Recordings. Несуществующая страница, сбой отрисовки и повторный заход на вход тоже возвращают на Home; логотип на этих экранах ведёт туда же. Со страницы записи по-прежнему можно вернуться в каталог.
- **Записи:** четыре одинаковые карточки показывают обработку, ожидание источника, паузу и ошибки. Каждая открывает каталог с соответствующим фильтром. Ниже — один список до пяти записей с вкладками **Recently added** и **With errors**. При наличии ошибок сначала открывается вторая вкладка; обновление данных не меняет выбор пользователя.
- **Активность:** под записями — просмотры публичных видео, число добавленных записей и часы транскрибированного материала за сегодня и шесть предыдущих дней по UTC. Метрики и график просмотров собраны в один блок; **View analytics** ведёт в Settings → Usage. Крупные числа сокращаются; значения до сокращения доступны в подсказках и экранному диктору. Часы округляются до одного знака после запятой.
- **Устойчивость:** ошибки загрузки отделены от пустых состояний. Уже загруженные записи остаются видны при сбое обновления; устаревшая пустая сводка не скрывает новые записи. **Try again** повторяет запрос нужного блока. Если сервер ограничил частоту запросов, интерфейс просит подождать и показывает срок, когда он известен. Квота, обрыв сети, слишком большой файл и ошибка сервера объясняются своим текстом, а не пустым списком.
- **Проверка:** локально проверены сетка на 320–1920 px, обе темы, длинные названия, крупные показатели, переходы всех четырёх статусов, отдельные ошибки запросов и восстановление. Браузерные проверки использовали тестовые API-ответы; это не проверка боевой нагрузки.


#### Добавление видео

- **Sources → File → Link** — порядок вкладок в Add video. Во вкладке Sources выбираются активные источники для синхронизации: список можно искать, выбрать показанные элементы или очистить выбор. Лимит — 50 источников за один запуск; при пустом списке есть переход в Sources. Технические типы источников заменены понятными названиями.
- **Локальный файл** — интерфейс получает допустимые расширения и предел размера от сервера, проверяет пустой файл, расширение и размер до отправки. Название записи берётся из имени файла без расширения и редактируется. После полной передачи сервер проверяет контейнер, длительность и квоту хранилища, затем сохраняет запись. Предел — не более 5000 MiB; настройка сервера может сделать его ниже.
- **Дозагрузка** — после обрыва в том же браузере нужно выбрать тот же файл в течение 24 часов. Клиент запрашивает фактическое смещение у сервера и отправляет остаток блоками по 8 MiB, включая неполный блок. В форме это обозначено плашкой `Resume: same file · 24h`. Показанные 100% означают конец передачи; до создания записи интерфейс показывает сохранение. Повтор завершения той же сессии не создаёт вторую запись. После истечения срока начинается новая загрузка.
- **Одно видео по ссылке** — поддерживаются YouTube, VK Video, Rutube и Vimeo. Предпросмотр показывает название, длительность и обложку, если площадка их вернула; название записи можно изменить до добавления. Поле **Max quality** недоступно до проверки ссылки, затем показывает `Best` и найденные разрешения до 4320p без повторяющегося `Up to`. Выбранное разрешение — верхний предел: при скачивании поток может быть ниже.
- **Плейлист YouTube** — принимается ссылка с ID плейлиста. Предпросмотр показывает число доступных и недоступных роликов на момент проверки; состав может измениться до импорта. Импорт создаёт по записи на доступный ролик в пределах оставшейся месячной квоты и обновляет уже добавленные без потери пользовательского названия и шаблона; при исчерпанной квоте импорт не начинается. Один предел качества применяется отдельно к каждому ролику; точное разрешение каждого ролика заранее не обещается. Недоступные, пропущенные по квоте и неудачные элементы отражаются в результате импорта.
- **Публичный Яндекс Диск** — пользователь выбирает **One video** или **Folder**. Предпросмотр проверяет тип ссылки, число подходящих видео и примеры имён; это число найденных файлов, а не обязательно новых записей. Сервер отклоняет несовпадение выбранного типа. Папка включает подпапки. Имя нового источника предлагается по имени файла или папки, у файла расширение убирается. **Save & sync** создаёт источник или повторно использует существующий и ставит синхронизацию в очередь. Качество берётся из оригинального файла; отдельного выбора разрешения здесь нет.
- **Запуск обработки** — галочка доступна на каждом пути: после загрузки файла, добавления ссылки или синхронизации источника. Если она выключена, локальный файл уже сохранён, а видео по URL и плейлисту добавляются как записи без скачивания; Диск и Sources всё равно синхронизируют список записей. Скачивание внешних видео и обработку можно запустить позже. Ошибки предпросмотра, неподдерживаемые ссылки, дубликаты и сбой постановки задачи показываются в форме; статус синхронизации обновляется после запуска.

#### Курсы, просмотр и сброс

- **Тема:** публичные запись, плейлист и канал следуют системной теме. Кнопка солнце/луна в шапке рядом с Copy link переключает вид; повторное нажатие снова следует системе. Тот же выбор, что в Settings.
- В плейлистах появились папки групп. Из видео, открытого в курсе, можно вернуться к его папке и плейлисту. Прямая ссылка на видео не раскрывает связанные плейлисты и каналы; переход к каналу требует проверенного контекста `?from=`. Копирование ссылки этот контекст убирает.
- Обновление временного адреса не пересоздаёт играющий `<video>`: новый адрес остаётся готовым для восстановления, если текущий перестанет работать. Это действует для публичной записи, видео в курсе и страницы владельца. Каталог запрашивает превью только для открытой страницы.
- Плановое обновление адреса учитывает время получения ответа из кэша. Для стандартного срока в один час запрос идёт примерно за две минуты до истечения; для срока до двух минут — через половину срока, в том числе если он короче минуты. Неудачный запрос повторяется до трёх раз: не позднее минуты, а при близком истечении ссылки — раньше. Совпавшие с фоновым обновлением запросы не отменяют друг друга.
- Во время воспроизведения плеер проверяет продвижение позиции. Если видимая вкладка или открытый PiP 30 секунд не получает прогресса, он запрашивает свежий адрес и пытается восстановить позицию и воспроизведение. Позиция на время восстановления хранится также в памяти, поэтому этот переход не зависит от доступности `localStorage`. При скрытой вкладке без PiP таймеры ожидания приостанавливаются.
- При восстановлении после ошибки сохраняется позиция даже в последних пяти секундах; обычное повторное открытие почти законченного видео по-прежнему начинается с начала. Смена вкладки сама по себе не ставит видео на паузу. Ручной PiP доступен в поддерживаемом браузере на широком экране; Chromium может запросить автоматический PiP для звучащего видео с учётом разрешения сайта. Плеер не открывает PiP принудительно на каждое скрытие вкладки.
- Ручная кнопка Retry дожидается ответа с новым адресом и запускает видео именно с ним; если обновление не удалось или адрес не изменился, повторяет попытку с текущим адресом. Запоздалый ответ Retry не переключает уже восстановленный или сменённый плеер. На странице владельца относительный адрес локального хранилища направляется на API, а не на домен фронтенда.
- При Play и Next в курсе команда воспроизведения привязана к выбранному ролику и выполняется после появления его `<video>`. Если браузер запрещает автовоспроизведение, зритель может нажать Play сам.
- Браузерная ошибка видео больше не сбрасывает намерение продолжить просмотр, если она сама вызвала `pause`. После двух неудачных автоматических восстановлений плеер прекращает цикл новых ссылок и оставляет ручную Retry; счётчик сбрасывается после устойчивого воспроизведения. Прямой доступ к удалённому, пустому или неготовому ролику курса теперь возвращает 404 для страницы, медиа и файлов.
- У запросов публичных данных и адреса видео есть предел в 30 секунд, у обновления сессии — тоже 30 секунд; серверное получение данных для заголовка публичной страницы ограничено четырьмя секундами. Эти пределы не относятся к прямой загрузке видео браузером из S3.
- **Остаётся ограничение:** уже играющее видео сохраняет прежний адрес до ошибки. Если после истечения срока браузеру нужен новый Range-запрос, возможны остановка и повторная буферизация перед восстановлением. Сетевые и браузерные остановки нельзя исключить только клиентским кодом. Публичный просмотр через локальное хранилище требует отдельного маршрута с проверкой share-ссылки и поддержкой Range; текущий локальный маршрут требует входа и отдаёт файл целиком. Проверка реального часового просмотра в браузере ещё не проведена.
- **Проверка:** `pnpm lint`, `pnpm build`, 36 тестов фронтенда, 1011 unit тестов backend, Ruff и `git diff --check` прошли локально. `ty check` завершился с кодом 0, но сообщил о 91 предупреждении типизации. Свежая база PostgreSQL прошла миграции 001–057. Safari WebDriver не запустился, потому что в браузере отключена настройка Allow Remote Automation; включение настройки требует пароль администратора. Эти проверки не измеряют время старта видео и не доказывают непрерывность долгого воспроизведения в браузере.
- Диалоги сброса предупреждают об удалении оригинального видео. Сброс с сохранением файлов оставляет медиа для повторной обработки.

#### Развёртывание

- Автоматическая сборка и выкладка ждут успешный CI для того же коммита; если до подтверждения появился новый коммит в `main`, устаревшая выкладка пропускается. Ручной запуск Deploy остаётся отдельным действием.
- Порядок выкладки и что подготовить на сервере — в [CHANGELOG.md](CHANGELOG.md) и [руководстве по развёртыванию](guides/DEPLOYMENT.md).

#### Отдельные вопросы

- Ручная обрезка видео в форме добавления и пересмотр политики хранения оригинального видео и аудио в S3 остаются следующими решениями; v0.11.1.0 их не меняет.

### 2026-05-11: v0.9.6.6 — релиз

Этот релиз выравнивает **одни и те же бизнес-правила** на всём пути видео: от выбора файла на Яндекс.Диске и загрузки через API до проверки после скачивания. Оператору и интегратору проще понять, *какие файлы платформа вообще принимает* и *как они лежат на диске*.

#### 📥 Один whitelist форматов
- Допустимые расширения видео заданы **централизованно** (кортежи `STORAGE_DEFAULT_*` в `config.settings`) и попадают во все сценарии: пикер Яндекс.Диска, загрузка записи через API, загрузка из Zoom / yt-dlp / публичных ссылок.
- Переменные **`STORAGE_SUPPORTED_VIDEO_FORMATS` / `STORAGE_SUPPORTED_IMAGE_FORMATS` в `.env` больше не меняют поведение** — список меняется только выпуском версии. Это убирает «тихие» расхождения между окружениями и тем, что реально поддержано кодом (в т.ч. sniff контейнера).

#### 🗂️ Файлы записей и диагностика
- Запись сохраняется как **`source.<расширение>`**, согласованное с именем/типом источника (Яндекс, Zoom `video_file_type`, имя при локальной загрузке). Раньше по умолчанию часто был «везде `.mp4`», что усложняло разбор проблем.
- После сохранения остаётся **проверка целостности**: не HTML-страница вместо видео, совпадение **расширения и реального контейнера** (например WebM/MKV vs MP4), базовый контроль размера.
